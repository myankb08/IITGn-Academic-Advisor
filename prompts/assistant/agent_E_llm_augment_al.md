# Agent E: LLM paraphrasing, augmentation (Part D), active learning (Part D)

Follow `prompts/assistant/agent_common_rules.md`. Local model server: Ollama on http://localhost:11434 with `qwen2.5:1.5b` pulled (CPU only, 8 cores, 6 GB RAM, about 4 GB disk free: do not pull large models). Record the model digest from `ollama show --modelfile` or `/api/tags` with every output. If CPU throughput is too slow for the full run (estimate it first with 5 calls), write `notebooks/kaggle_llm_runs.ipynb` that does the same calls with transformers `Qwen/Qwen2.5-1.5B-Instruct` (pin the HF revision hash) reading the same prompt files, and report the time estimate so the orchestrator can decide.

The engine agent is regenerating `data/processed/queries.jsonl` right now (about 400 to 450 pairs, three programmes). Build and test against `tests/fixtures/fixture_queries*.jsonl` first; run for real only when the orchestrator tells you, or if queries.jsonl has been stable (unchanged mtime) for 10 minutes and supporting_files/B_engine/queries_summary.json mentions MTech-EE.

1. `src/queries/paraphrase_llm.py`: for every pair, ask the LLM for (a) a paraphrase of `query_text` that keeps every course code and constraint, and (b) a short student-friendly justification rewritten from `gold_text`. Prompts in `prompts/pipeline/paraphrase_query_v1.txt` and `paraphrase_justification_v1.txt`, loaded by the code, ids stored in `para_prompt_id`. Seeded (`seeds.paraphrase`, Ollama `seed` option), temperature from params.yaml. Cache by (prompt id, input hash, model digest) in `data/interim/llm_cache.jsonl` so reruns are free and deterministic. Do not filter or fix outputs: errors in paraphrases are what humans audit. Write `data/processed/queries_para.jsonl` and a run log `supporting_files/C_labelling/paraphrase_run.json` (counts, timings, model digest).
2. Augmentations in `src/augment/` (seed `seeds.augmentation`), each producing children with `augmentation` and `parent_query_id` set:
   - `paraphrase.py`: a second LLM paraphrase of the query (different prompt `prompts/pipeline/augment_paraphrase_v1.txt`).
   - `typos_abbrev.py`: rule-based typos (keyboard-adjacent swaps, dropped letters, never inside course codes) and abbreviations from a documented dictionary (e.g. "ML" for Machine Learning, "algo", "sem", "elec", "reqs", "pre-req"), plus course-code format variants ("CS610", "cs-610").
   - `transcript_variants.py`: reorder transcript entries, and vary transcript length by moving a student to an earlier semester snapshot (truncation creates a new state, so recompute gold for that new state and mark it as a new derived pair) vs reorder (gold must be identical).
   - `src/augment/verify.py`: for every child, rerun the rule engine and check the gold answer is unchanged (for reorder, typo, paraphrase) or correctly recomputed (truncation). For the text augmentations also check every course code from the parent still resolves after normalisation. Children that fail are dropped and listed. Report invariance rate per augmentation to `supporting_files/D_augmentation/invariance.csv` and 10 before/after samples per augmentation in `supporting_files/D_augmentation/samples_<aug>.md` for human spot checks. Output `data/processed/queries_augmented.jsonl`.
3. Active learning in `src/active/`:
   - `base_model_answers.py`: base model `qwen2.5:1.5b` (temperature 0, prompt `prompts/pipeline/base_model_answer_v1.txt`) answers every query in the unlabelled pool given the student summary and a compact catalog context, asked to return JSON in the same shape as gold_json. Cache like above.
   - `disagreement.py`: informativeness score = disagreement with the rule engine (1 - Jaccard over course code sets, plus wrong eligibility boolean, plus invalid JSON = max, plus hallucinated codes not in courses.json). Document the formula.
   - `al_vs_random.py`: budgets from params.yaml, AL picks top-k by score (ties by seeded shuffle), random picks average over the 5 seeds in `seeds.active_learning`. Metrics per budget: share of all base-model failures captured, share of failure types covered (hallucinated code, wrong eligibility, wrong remaining, invalid JSON), and number of distinct programmes/intents covered. Plot `supporting_files/D_active_learning/label_efficiency.png` with the CSV behind it, and write a short `summary.md`. Pool = train-candidate pairs only (exclude anything the split script marks test if splits exist, else note it).
4. pytest tests for typo augmentation never touching course codes and for the verify step.

Report timings, counts, invariance rates, and the AL vs random numbers.
