# Agent A: Part A collection and curriculum knowledge base

Follow `prompts/assistant/agent_common_rules.md`.

Goal: turn the sources in `data/raw/sources/` into the raw and processed curriculum layers defined in `docs/DATA_CONTRACT.md`, with full provenance, for the CS discipline M.Tech programmes (MTech-CSE, MTech-AI).

Build in `src/collect/`:
1. `extract_sources.py`: pdfplumber over every PDF, page-level rows to `data/raw/extracted/pages.jsonl`; openpyxl over the timetable xlsx (sheet "Time table"), one row per course row with the hyperlink target of the "Link To Course Plan" cell, to `data/raw/extracted/timetable_rows.jsonl`. Record tool versions.
2. `fetch_course_plans.py`: for the course codes relevant to CS M.Tech (everything named in "Revised CSE MTech Course Structure [2025-26].pdf", plus CS 6xx/ES 6xx courses in the timetable), download the course plan. Google Docs: `https://docs.google.com/document/d/<id>/export?format=txt`. Drive files: try `https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t`. Save to `data/raw/course_plans/<CODE>.<ext>` and log url, http status, timestamp, sha256 to `supporting_files/A_collection/course_plan_fetch_log.csv`. Failures are logged, not fatal. Be polite (sleep 0.5s between requests).
3. `build_catalog.py`: produce `data/raw/catalog_raw.json` keeping source defects as found (duplicate CS 618 in the AI/ML basket, "Algrithms" typo, float credits like 4.0, section suffixes like "(E)"). Then a cleaning step `clean_catalog.py` produces `data/processed/courses.json` and writes every change to `supporting_files/A_collection/cleaning_changes.csv` (record id, field, before, after, reason). Credits come from the timetable C column where available, otherwise from the course structure or a stated default with `credits_source` noted.
   Prerequisites: extract from course plan text (look for "prerequisite", "pre-requisite", "prereq", "background", "recommended"), store the evidence line. Only store codes that are explicitly named or titles that map unambiguously to a catalog course. If a plan says none, `none_stated`. Courses without plans get `none_stated` with evidence "no course plan available". Put any manual decision in `data/raw/prereq_manual.csv` with a reason column, and use `prereq_source: manual`.
4. `build_rules.py`: from Adv5_NormsforMTechProgramme.pdf, Adv17, Adv24, Adv42 and the CSE structure, write `data/processed/rules.json` with each number linked to source_doc and source_page. Read the PDFs carefully (they are short). Courses like Writing, HSS, Aarohan, Applications of AI, thesis units and project courses become `category: requirement` pseudo-entries or rule entries; check what codes the timetable uses for them, otherwise use clearly named placeholders such as `REQ-WRITING` and document that.
5. `build_metadata.py`: write `data/metadata.csv` per the contract covering every raw file, every extracted page/row, every course plan, and every processed course record. collector = "hem436" for human-supplied sources, "pipeline" for automated steps.
6. Docs: `docs/CONSENT_AND_LICENSING.md` (institute documents are public IITGN academic regulations used for non-commercial coursework; course plans are linked publicly from the timetable; Google Forms respondents: anonymised IDs only, consent checkbox text, no names/emails stored; synthetic students contain no personal data) and `data/consent_register.csv` with header only (respondent_id, consent_given, date, form_version) since responses are not collected yet. `docs/DATA_FLOW.md` with a Mermaid diagram from sources to metadata.csv and onwards. `supporting_files/A_collection/collection_log.md` summarising runs and counts.
7. A `dvc.yaml` stage list is handled by someone else; just make each script a single command.

Run everything end to end and report counts: pages, timetable rows, plans fetched/failed, courses in raw vs processed, courses with prerequisites, rules extracted.
